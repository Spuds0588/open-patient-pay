      Deployment

      Spin it up in one command

      A single docker compose up -d brings up Postgres (on a persistent volume) and the stateless app. It runs on anything that can run Docker — no Kubernetes, no vendor lock-in.

      1

      Clone

      git clone https://github.com/Spuds0588/open-patient-pay.git
cd open-patient-pay
      2

      Configure

      cp .env.example .env
# edit DATABASE_URL, APP_BASE_URL,
# plan limits, Stripe keys, SMTP…
      3

      Launch

      docker compose up -d
docker compose exec app \
  npx prisma db seed   # demo data

      Migrations run automatically on boot. Backups are a one-liner pg_dump (see the README).

      Runs anywhere · processes with anyone

      No lock-in, on either side

      Because the app is stateless and every external dependency sits behind an adapter interface, you can host it on your favorite platform and swap processors without touching business logic.

      Hosting providers

      Bare-metal VPS Hetzner DigitalOcean AWS Lightsail Fly.io Render Railway Coolify Any Docker host

      Postgres runs in a named Docker volume, so a container crash never costs you data — and self-hosters keep 100% of their PHI.

      Payment processors & EHRs

      Stripe built-in Square via adapter Adyen via adapter Braintree via adapter FHIR R4 Epic · Cerner · athena CSV any practice mgmt export SMTP magic links · receipts · reminders

      The PaymentAdapter and DataIngestionAdapter interfaces mean a new processor or EHR feed is a drop-in module, not a rewrite.
